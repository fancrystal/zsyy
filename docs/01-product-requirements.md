# 需求与功能范围

## 角色

- 用户：手机访问，使用产品券购买，查看自己的订单、团队和返利。
- 管理员：通过独立后台维护内容和商品、发放产品券、查询运营记录。
- 开发者：初始化系统账号、维护数据库、运行补算和对账，不提供面向用户的修改上下线入口。

## 手机端

### 首页 `/`

展示公司名称、介绍和图片。公司介绍由后台维护；首版采用纯文本和结构化图片字段，不执行任意 HTML。

### 商城 `/mall`

展示已上架商品的图片、名称、产品券价格和简介。详情页 `/products/:id` 展示说明、数量输入和下单入口。用户登录并填写默认地址后，确认商品、数量、总消耗及地址，提交下单。成功后展示订单结果。

首版使用商品当前价格计算订单，服务端重新校验上架状态、价格及余额。单商品支持整数数量，不设购物车、多规格、优惠券、在线支付或线上库存扣减。页面明确提示下单后不支持取消、退款。

### 订单 `/orders`

按时间倒序分页展示本人订单，详情 `/orders/:id` 展示订单号、创建时间、商品快照、数量、消耗券数和地址快照。订单成功后为完成购买记录，无确认收货、退款、取消、物流追踪或线上发货状态。

### 管理 `/me`

展示个人资料、产品券余额及收支明细、默认收货地址、邀请码和邀请链接、直属下线、各子市场累计消费、最大市场标记、累计应得及已发返利、返利明细。用户只查询自己的团队统计，不提供任意浏览他人地址、余额的能力。

登录、注册和地址编辑作为辅助页面，不增加底部导航项。注册需填写有效邀请码，绑定后不提供修改入口。

## 独立后台

| 模块 | 首版操作 |
| --- | --- |
| 公司介绍 | 编辑文字和展示图片 |
| 商品 | 创建、编辑、上架、下架；已产生订单的商品不物理删除 |
| 用户 | 分页查询、查看账户和关系，不提供日常更换上线入口 |
| 发券 | 给指定用户发放正数产品券，记录操作人、备注和流水 |
| 订单 | 分页查询、条件筛选、查看商品及收货信息 |
| 团队与返利 | 查询关系、市场累计消费、累计应得和发放记录 |
| 任务记录 | 查看补算结果、失败和账务异常 |

后台无充值、收款、提现、退款、取消订单功能。批量导出、复杂权限分级和消息通知不纳入首版。

## 核心验收场景

1. 使用有效邀请码注册后，有且只有一个上线；无效邀请码不能创建账户。
2. 后台发券后余额增加，同步产生可追溯的流水。
3. 默认地址缺失或余额不足不能下单，失败不能产生部分扣款。
4. 成功订单保存商品和地址快照，修改商品或地址不能改变历史订单。
5. 下单后相关祖先的子市场累计消费更新，产生应有的差额返利。
6. 同一请求重试、返利重算和每日补查均不会重复扣券或发券。
7. 用户只能看到自己的订单和资产；用户身份不能访问后台接口。
