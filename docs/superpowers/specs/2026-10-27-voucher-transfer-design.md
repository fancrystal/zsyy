# 产品券用户间转账设计

日期：2026-10-27。

## 已确认规则

- 用户可使用已注册的 11 位手机号向任意其他用户转产品券；手机号是收款人的唯一识别方式。
- 不可向本人转账。
- 转账实时到账、免手续费、不可取消或退款。
- 最小转账金额为 0.01 券，最大不超过付款人可用产品券余额。
- 转账仅移动产品券余额：不计消费，不触发 20% 直推收益、10% 团队返利或每日补查收益。
- 用户端必须提供转账入口及本人转入、转出明细。

## 数据与账本模型

新增 `voucher_transfers` 表，字段包括：`id`、唯一 `transfer_no`、`sender_user_id`、`recipient_user_id`、正数 `amount_units`、`note`、`idempotency_key`、`request_hash`、`created_at`。对付款用户的幂等键设置唯一约束 `(sender_user_id, idempotency_key)`。

每个转账单在同一 MySQL 事务内产生两条关联钱包流水：

- 付款方：`type=transfer_out`，负数金额，标题“转出产品券”，来源键 `transfer:<id>:out`。
- 收款方：`type=transfer_in`，正数金额，标题“收到产品券”，来源键 `transfer:<id>:in`。

转账单、双方钱包余额和双边流水要么全部提交，要么全部回滚。钱包余额仍必须等于该用户所有钱包流水净额。

## API 与事务流程

新增受用户会话保护的 `POST /api/transfers`：

```json
{
  "recipientPhone": "13123456789",
  "amountUnits": 10000,
  "note": "赠送产品券"
}
```

请求必须带 `Idempotency-Key`。服务端在一个全局账务事务中依次：

1. 校验收款手机号、金额、备注、幂等键和付款账户完整性。
2. 查找收款人，拒绝不存在的手机号和本人转账。
3. 以行锁读取付款余额，拒绝余额不足；付款或收款账户存在账务异常时拒绝。
4. 创建转账单，扣减付款方余额并写 `transfer_out` 流水，增加收款方余额并写 `transfer_in` 流水。
5. 提交事务并返回转账详情；同幂等键、同内容重试返回原转账，不再移动余额；同键不同内容返回冲突。

新增 `GET /api/transfers`，只返回当前用户作为付款方或收款方的转账记录，按时间倒序分页。每条返回对方用户名、对方手机号、方向（转入／转出）、金额、备注、时间和转账编号。管理端不新增主动转账能力，既有用户钱包流水可审计双边记录。

## 用户端

个人管理页增加“转产品券”入口：填写收款手机号、金额和可选备注，显示当前可用余额，提交期间禁用重复操作。成功后刷新余额和最近流水。

个人管理页增加“转账明细”入口：展示转入、转出记录，方向、对方用户名／手机号、金额、备注、时间与转账编号；支持加载更多分页。普通“收支明细”也保留对应的转入／转出钱包流水。

## 对账与验收

对账将扩展为校验每个 `voucher_transfers` 记录都恰有一条付款方负流水和一条收款方正流水，双方用户、金额和来源键一致；任一缺失或不匹配将记录异常并隔离相关账户。

验收须覆盖：成功转账、余额不足、收款手机号不存在、本人转账、幂等重试、并发转账不能超额、双边明细可见、转账不改变市场消费和两类收益、对账不重复转账。
