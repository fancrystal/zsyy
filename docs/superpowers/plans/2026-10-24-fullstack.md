# 本地完整业务实施计划

用户已授权继续补齐检查报告中的未实现功能，并允许启动现有 Docker/MySQL；沿用已确认的设计，保持独立数据库，不操作 mskj 业务数据。

目标：让现有双端通过 Express + MySQL 真实运行账号、商品、订单、产品券与累计差额返利。

技术：现有 Vue 3、Vite、Element Plus；新增 Express、mysql2、bcryptjs、JWT、cookie、输入校验。Redis 不是账务依据；首版使用数据库锁协调任务，无 Redis 时不影响账务正确性。

## 接口及文件边界

- `packages/backend/src/db/`：连接配置、建表迁移、独立开发和测试库。
- `packages/backend/src/services/`：账号、商品、账务、订单、团队及定时补算；统一事务传递连接。
- `packages/backend/src/app.js`：JSON API、用户/管理员身份隔离、统一业务错误。
- `packages/backend/src/index.js`：启动、每日任务及关闭。
- `packages/backend/tests/`：真实 MySQL 集成测试及 API 测试，不以 SQLite 或内存替代。
- `packages/shared/api.js` 与 `store.js`：同源 fetch、身份和服务器数据；原演示模型仅保留为独立预览/旧测试参考，不再作为真实余额来源。
- 手机端增加登录注册、资料编辑、邀请链接；后台增加登录、新增商品、用户详情和筛选、指定用户发券、订单筛选分页、真实返利与任务记录。

## 事务策略

首版优先简单可靠：所有影响余额、订单和团队消费的操作先锁定同一数据库互斥行，再更新各账户。避免树上多账户并发死锁及补查覆盖新订单，代价是账务写入串行；后续实际吞吐需要时再细化锁粒度。幂等仍由数据库唯一键和请求内容校验保障。

## 验收例子

建立根用户 A，直属 B/C/D，B 下 E；E 消费只归 A 的 B 市场、B 的 E 市场。A 市场累计 10000/6000/4000 时累计应得1000；已发800只补200；原最大增长不补；另一市场增长超越后按新最大重算。发券/返利入账不是消费。失败交易不能留下部分扣款、订单或返利。
