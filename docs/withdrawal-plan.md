# 提现功能实施计划

## 已确认规则

- 所有产品券余额可申请提现；每次至少 50 券，且为 50 券的整数倍。
- 手续费为申请数量的 6%；申请 100 券扣除 100 券，线下转账 94 元。
- 收款方式为支付宝；管理员审核通过后线下转账，并上传凭证及记录流水号。
- 待审核申请可驳回，驳回时原额退券；已审核申请不自动退券。

## 实施顺序

1. 增加提现记录及收款账号加密配置，保存金额、费率、收款快照、状态、审核与打款信息。
2. 利用现有钱包事务和流水实现申请、幂等重试、余额检查、审核与原额退券，并扩展账务核对。
3. 用户端增加申请入口、手续费预览、密码验证、申请记录与凭证查看。
4. 管理端增加提现列表、收款信息查看、审核、驳回、凭证上传及线下转账确认。
5. 测试金额规则、并发和幂等、余额不足、权限隔离、状态流转、凭证访问和账务一致性，运行测试及构建。

## 关键约束

- 金额以项目现有整数单位计算，手续费由服务端计算并保存在申请记录中。
- 收款账号加密存储，默认脱敏；凭证仅申请人及有权限的管理员可访问。
- 生产环境使用独立的 `WITHDRAWAL_ENCRYPTION_KEY`，必须安全备份并保持稳定；更换密钥前须先迁移历史收款账号密文。
- 扣券、提现记录和流水在同一数据库事务中提交；驳回和退券同样原子执行。
- 提现请求复用幂等键，重复请求不能重复扣券；审核和打款状态更新需防止并发重复处理。
