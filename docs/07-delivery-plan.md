# 分阶段实施与验收方案

本文件是阶段路线图，不是已经执行的开发记录。各阶段开始前再编写针对该阶段的文件级实施步骤和必要测试，不一次性开发全部系统。

目标：以参考项目技术栈构建手机产品券商城和独立后台，逐步形成可验证的业务闭环。

## 阶段一：项目骨架与数据基础

主要文件：根 `package.json`、`pnpm-workspace.yaml`、`.gitignore`、`.env.example`；`packages/mobile-h5`、`packages/admin` 的 Vite 入口及路由；`packages/backend/src/app.js`、`index.js`、`config/`、`db/migrations/`。

- [ ] 核对本机运行环境和参考项目依赖，固定兼容版本及锁文件。
- [ ] 建立 workspace、两个前端、后端健康接口和统一错误响应。
- [ ] 按数据库设计创建迁移，提供独立开发及测试库配置。
- [ ] 建立手机四页导航和独立后台布局。
- [ ] 更新实际启动、构建和迁移命令到 README。

验收：两个前端可构建、后端可启动、健康接口可访问；空库可迁移，重复执行迁移不会破坏数据。此阶段不声称已支持真实下单。

## 阶段二：账号、邀请关系、默认地址和钱包

主要目录：后端 `modules/auth`、`users`、`teams`、`wallets`，`maintenance/`；手机端登录、注册、管理和地址页面；后台用户及发券页面。

- [ ] 编写有效/无效邀请码、重复用户名、权限隔离和发券幂等的服务测试。
- [ ] 实现根用户及管理员初始化、用户注册登录及关系绑定。
- [ ] 实现钱包和返利账户初始化、默认地址保存及本人资料查询。
- [ ] 实现后台发券与流水，同一事务提交。
- [ ] 对照真实 MySQL 验证并发发券及失败回滚。

验收：新用户通过邀请码绑定；无换上线入口；本人资料不能越权读取；后台发券重复请求只到账一次；余额与流水一致。

## 阶段三：商品、下单与购买记录

主要目录：后端 `modules/content`、`products`、`orders`；手机首页、商城、详情和订单页；后台内容、商品和订单页面。

- [ ] 编写余额不足、缺地址、下架商品、价格变化、重复请求、并发超余额及快照不变的测试。
- [ ] 实现公司介绍和商品管理，并连接手机展示。
- [ ] 实现订单事务、商品及地址快照、扣券和消费流水。
- [ ] 验证成功订单与消费流水一一对应，所有失败路径整体回滚。
- [ ] 在本阶段验收环境验证订单闭环；真实下单开放前必须接入下一阶段的市场累计及返利事务。

验收：用户用产品券完成购买并查询记录，不能退款或取消；网络重试不重复下单；历史商品及地址不被后续编辑改变。阶段三仅完成订单模块，整个业务闭环在阶段四完成。

## 阶段四：市场累计及差额返利

主要目录：后端 `modules/teams`、`rebates`，对接 `orders` 与 `wallets`；手机管理页团队及返利区域；后台返利查询。

- [ ] 先实现纯计算函数测试：零市场、单市场、三市场、并列最大、最大市场切换、小额累计舍入。
- [ ] 测试多级祖先归属、本人消费不进入本人市场、每个祖先只累计一次。
- [ ] 实现市场更新、累计应得、正差额补发，并纳入下单同一事务。
- [ ] 用真实 MySQL 验证同一上级多个下线并发下单，以及下单与补算并发。
- [ ] 验证已发累计、返利记录和钱包流水完全一致，重复重算补发为零。

固定验收数据：市场为 10000、6000、4000 券，已发 800 券，本次发 200 券；第一市场增至 12000 后补发 0；第二市场增至 15000 后再补发 600。多级关系测试需逐级独立核算，不能只检查第一层。

## 阶段五：每日补查、维护与上线准备

主要目录：后端 `jobs`、`maintenance`；后台任务和异常查询；运行文档及部署配置。

- [ ] 测试任务重试、服务重启漏跑、并发任务、消费汇总偏差、源账异常和负差额。
- [ ] 实现每日定时补查、持久化进度及按日期补跑。
- [ ] 提供初始化、账务对账、市场汇总重建和幂等返利补算维护命令；危险变更不开放普通后台按钮。
- [ ] 验证数据库备份及恢复，检查生产配置和权限隔离。
- [ ] 在实际手机浏览器验证四页导航、登录、发券后购买、地址快照、订单及返利查询。

验收：任务重复执行不重复发券，维护后可定位并处理异常，部署后可完成完整业务演示。上线部署时间及环境由用户在部署阶段指定。

## 全局验证原则

金额、返利公式、账户权限、并发和事务必须有有效测试；静态文案和低风险布局以构建及人工检查为主。测试需验证业务结果和不变量，不能仅复制实现。所有账务集成测试使用独立测试库，不连接生产库。

实施命令在脚手架落地后固定，例如根目录统一提供开发、构建、测试、迁移和维护入口；当前不存在这些脚本，不能把规划命令当作可用命令执行。
