## 决策状态

用户已确认：四个手机页面、独立后台、产品券消费、后台发券、无现金交易、无退款取消或确认收货、默认地址及线下发货、邀请码单上线关系、累计最大市场排除、10% 累计差额返利、消费变化触发重算并每日补查。

以下是用于使设计可实施的建议默认值，不代表用户已经逐项确认：

| 项目 | 建议默认值 |
| --- | --- |
| 项目显示名称 | 产品券商城；正式名称和公司文案在内容配置阶段提供 |
| 登录方式 | 用户名和密码，不接入短信服务 |
| 产品券精度 | 0.01 券；数据库存整数最小单位 |
| 返利舍入 | 对累计应得统一向下取整到 0.01 券 |
| 每日补查时间 | 北京时间 02:00，可配置 |
| 首版购买 | 单商品、多数量直接下单，不做购物车、多规格或库存系统 |
| 收货地址 | 每人维护一个默认地址；下单必须存在有效地址 |
| 后台账号 | 独立于用户账号，仅开发者初始化，不开放管理员注册 |
| 邀请入口 | 邀请码展示、复制邀请链接；二维码可后续增加 |
| 异常负差额 | 记录异常并停止该用户自动补发，不自动扣回历史返利 |

实施每个阶段前检查这些默认值；涉及用户操作和金额口径的变动需同步更新文档。品牌视觉、部署环境和具体依赖版本在对应阶段确定，不阻塞本次文档交付。
